**Key R1 finding, not a guess — directly observed:** storefronts 1 and 2 are **already** the same Vakaviti-adjacent backend (one Worker, one D1, one admin queue). The Issue #37 "one Vakaviti Fare Authority" goal is *already true in practice* for these two; the real remaining work for them is (a) adding a `BookingSource`/brand-attribution column so a shared queue can still tell them apart, and (b) formalizing the shared pricing logic behind an explicit contract/versioned service rather than leaving it as one Worker's internal function. This materially changes the Phase 5 cutover recommendation (see the main report) — there is no "shadow parity" question to prove between storefronts 1 and 2, only a labeling gap.
