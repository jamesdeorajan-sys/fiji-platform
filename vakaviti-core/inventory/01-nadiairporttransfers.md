| Quote endpoint(s) | `GET https://api.nadiairporttransfers.com/reference-fare?pickup_zone=&destination_zone=&vehicle_type=&trip_type=` — real-time, distance-based (Google Maps Distance Matrix via `GOOGLE_MAPS_API_KEY`), tiered `pricing_rules` lookup, fuel-index multiplier, night surcharge, return-trip multiplier, >$50 auto-discount. Cached in `zone_distance_cache` (`"cached": true` on repeat calls). Also `POST /quote` for a geocoded custom/unmapped address (Milestone 9). |
| Booking create endpoint(s) | `POST https://api.nadiairporttransfers.com/bookings` |
| Booking reference format | Client-generated `FD-XXXXXX` (6 uppercase alphanumeric, e.g. `FD-JJW597`), sent to the server as `client_booking_ref` and stored verbatim; also the value shown to the guest as "Request ref". Server also returns an internal integer `booking_id` (D1 autoincrement `bookings.id`). Staff can look up by either today, informally — no unified `VK-...` ID yet. |
| Production data store(s)/bindings | D1 `nadi-marketplace-db` (id `0ec1cd84-fcda-4f7f-8337-0fb70fe1a512`) — table `bookings` plus `zones`, `pricing_rules`, `fuel_index`, `platform_settings`, `negotiation_requests`/`negotiation_offers`, `drivers`, `escalations`, `wallets`, etc. (23 tables). R2 `nadi-marketplace-driver-docs` (binding `DOCS`), R2 `nadi-marketplace-db-backups` (binding `BACKUPS`). No KV, no Vectorize — deliberately isolated from the Lagi/vakaviti-kb stack. |
| Vehicle taxonomy | `sedan`, `minivan`, `minibus`, `boat` (`ALLOWED_VEHICLE_TYPES` constant in `worker.js`). No distinct "SUV/people mover" class — minivan is the closest equivalent shown publicly. Boat is excluded from `/negotiate` and `/reference-fare` by design (third-party bundled price, not FTT-set). |
| Route/location identifiers | Named `zones` table rows (`Nadi`, `Nadi Airport`, `Wailoaloa`, `Denarau`, `Sonaisali`, `Vuda Point`, `Lautoka`, `Momi Bay`, `Natadola`, `Sigatoka`, `Coral Coast`, `Pacific Harbour`, `Ba`, `Rakiraki`, `Suva`, `Nausori`, `Mamanuca Islands`, `Yasawa Islands`, `Beqa Lagoon` — 19 rows total, each with lat/lng + a `remote_multiplier`). Guest-facing hotel picker maps ~55 named hotels to one of these zones (see `ftt-booking-site/src/app.js` hotel→zone table). Custom addresses go through `/quote`'s geocoding path instead of a zone id. |
| Fare calculation inputs | `pickup_zone`, `destination_zone` (or geocoded lat/lng for custom), `vehicle_type`, `trip_type` (`one-way`/`return`), `pickup_time` (for night surcharge), `has_child_seat`, `has_surfboard`, `is_custom_address`, `has_tour`. Tiered `pricing_rules` (`distance_min_km`–`distance_max_km`, `base_rate_fjd_per_km`, `flagfall_fjd`, per vehicle type) + live `fuel_index.multiplier` + 20% night surcharge (10pm–6am) + 1.85× return multiplier + 10% auto-discount over $50. |
| Guest/contact fields | `guest_name`, `guest_phone` (normalised), `guest_email` (added milestone34, nullable), `notes`. |
| Flight fields | `flight_number` (added milestone34, nullable, free text, no airline-schedule validation). |
| Return-trip representation | Single `bookings` row per outbound leg; `trip_type` recorded implicitly via pricing at quote time, but the actual DB schema stores `return_date`/`return_time`/`return_pickup_location` on the SAME row as the outbound leg (Milestone 17), not as a separate linked booking. No multi-leg/itinerary object. |
| Brand/source attribution | None structured. `source_ip` is captured per booking; no UTM/referrer/storefront-id field distinguishes a booking placed via nadiairporttransfers.com vs book.fijidash.com — **they share the exact same backend and D1 table with no source discriminator column.** This is a real gap against Issue #37's "BookingSource" requirement, not an oversight in this inventory. |
| Current notification path | `broadcastBookingToDrivers()` (WhatsApp to zone-matching online drivers) + `sendHealthAlertWhatsApp()` to every `admin_alert_phone` in `platform_settings` (currently `+61 478 886 145`), both fired unconditionally on real (non-idempotent-replay) booking creation. Guest-side WhatsApp is optional (post-Issue-#34 fix) — a pre-filled `wa.me` link shown after server-side success, not required to complete a booking. |
| Current admin/ops handoff | `admin-bookings.html` (Direct Upload static page) reading `GET /admin/bookings` (Bearer `ADMIN_TOKEN` or a PIN-issued session token from `admin_login_tokens`). Shows id, guest name/phone/email, route, vehicle, fare, status, flight, client_booking_ref, driver assignment. `POST /admin/bookings/manual-assign` for manual driver assignment. |
| Exact rollback target | Worker: `wrangler rollback --version-id 5349af64-2f3d-43ac-901e-975257cfa3fa` (the pre-Issue-#34 production version). Frontend: redeploy git commit `cc53ea6` via `wrangler pages deploy` (verified byte-reproducible as of the PR #35 release). | Current live booking dependency chain | Guest widget (`ftt-booking-site/src`) → `POST /bookings` on `nadi-dispatch-api` → D1 `bookings` insert (idempotent on `client_booking_ref`) → `broadcastBookingToDrivers()` (driver WhatsApp) + `sendHealthAlertWhatsApp()` (ops WhatsApp) → guest sees success card → guest optionally opens WhatsApp. Admin visibility via `admin-bookings.html`. No queue/worker-to-worker hop; everything happens synchronously inside the one `POST /bookings` request. |
