## Scenario 2 — unknown economics -> HOLD, even with a strong match

`SYN-0003` (Nadi Town -> Nadi Airport) is a nearby-reverse candidate of
`SYN-0002`'s outbound leg, scoring 75, but `SYN-0003` itself has no
`operator_payout`/`absolute_floor` on file:

```
Booking ref: SYN-0003
Match score: 75
Recommended action: HOLD
```

This is the hard rule in action — a real, plausible match still resolves
to HOLD rather than a guessed price, because `smartMatchPrice`/
`enforceFloor` refuse to invent a floor.

## Known limitation surfaced by this run (see CEO_RELEASE_REPORT.md #15)

In the 7-day board run (`nowIso = 2026-09-20`), `SYN-0007`'s outbound leg
falls inside the visible 7-day window but its return leg (`SYN-0008`, one
day later) falls just outside it. The board correctly shows `SYN-0007` as
unmatched/a predicted empty leg *within this window*, even though its
actual return exists in the ledger — the board's matching pool is
intentionally limited to what's visible in the current 7-day slice. This is
disclosed as a known Stage 1 limitation, not fixed silently.
