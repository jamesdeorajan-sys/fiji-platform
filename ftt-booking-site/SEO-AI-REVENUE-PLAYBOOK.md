## Page optimisation standard
Every commercial route page should expose, where verified:
- clear origin and destination in title/H1
- price or explicit quote path
- travel distance/time
- vehicle capacity
- luggage guidance
- flight-delay handling
- cancellation/modification rules
- direct booking CTA above the fold
- WhatsApp fallback
- canonical URL
- Open Graph metadata
- FAQ structured data
- breadcrumb structured data
- Service/Offer structured data where appropriate
- visible related-route links to prevent dead-end sessions

## AI discovery standard
- OAI-SearchBot allowed
- OAI-AdsBot allowed
- GPTBot/ChatGPT-User allowed
- ClaudeBot and PerplexityBot allowed
- current llms.txt with verified route/pricing facts
- sitemap current
- machine-readable facts must match visible page facts
- avoid unsupported superlatives or invented availability

## Revenue measurement
Track each qualified enquiry and booking with:
- landing page
- source / medium
- campaign
- ChatGPT referral when present
- Google organic/search ads
- Meta campaign
- WhatsApp handoff
- booking reference
- booking value
- return-transfer upsell
- tour/activity upsell

## Guardrails
- no new websites
- no DNS changes in optimisation work unless separately approved
- no production deployment without regression checks
- no customer-specific booking pages indexed
- no change to booking confirmation truth model
